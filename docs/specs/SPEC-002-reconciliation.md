# SPEC-002: Asset Reconciliation

`Decide(observation, candidates, policy)` chooses an asset key and returns a merge plan. The Go and GLib C APIs use the
same algorithm. Applications supply eligible active identifiers and candidates, enforce access and scanner/network
boundaries, generate keys, retain evidence, and apply results atomically. The library does not store results, read
history, or use the wall clock.

## Inputs and results

- `Observation`: incoming `Identifiers`.
- `Candidate`: an existing `AssetKey`, its `Identifiers`, and optional `LastSeen`. Supply one candidate per key.
- `Decision`: the action, matching stage, selected key/index, and merge indices.

| Action   | `NeedsNewKey` | `SelectedKey` / `SelectedIndex` | Merge destination                    |
|----------|---------------|---------------------------------|--------------------------------------|
| `CREATE` | true          | Empty / nil                     | New key generated by the application |
| `REUSE`  | false         | Existing key / its input index  | Selected candidate's key             |

`Stage` is `STRONG` or `FUZZY`. Either action can have `MergeIndices`: original candidate positions to move to the
destination key. Preserve candidate ordering until applying the result. An empty merge list means no moves. Invalid
input returns an error and a zero decision. Inputs are not changed or retained; returned data is independent. Concurrent
calls may share immutable inputs. Complete scope, including nil versus empty, matters in every comparison. See [
`reconciliation.go`](../../identity/reconciliation.go) for the Go types.

## Policy

`MatchPolicy` contains `StrongOrder` and ordered fuzzy members (`Type`, `Weight`).
`GreenboneMatchPolicy()` uses this strong priority, highest first:

Cloud identifier → Greenbone ID → Machine ID → BIOS UUID → Agent ID → SSH host key → TLS public-key hash.

Default fuzzy members, in score accumulation order, are MAC (1.0), hostname (0.4), IP (0.4), and FQDN (0.4). Hostname
and FQDN are distinct types; compare their full normalized names.

Callers may reorder, reclassify, or omit supported types. An empty list disables that stage; it does not restore
defaults. An empty policy is valid. Reject unknown types, duplicate members, and types in both stages. Weights must be
positive, finite, and representable as positive finite float32. Defaults and clones own their slices.

## Strong matching

Normalize all views once using [SPEC-001B](SPEC-001B-normalization.md); omit placeholders and duplicates as evidence. A
raw `x509:` certificate counts only if its subject CN or a DNS SAN equals a hostname or FQDN in the same view:
ASCII names, case-insensitive, final dot ignored, no wildcards. Convert admitted certificates to SPKI hashes; supplied
`spki-sha256:` hashes remain eligible. `EvaluateStrongPriority` and `MatchingIdentifiers` apply the same admission
rules.

1. Compare the highest-priority strong type present in each view. A stored key can be reused only if its highest type
   has the same or higher priority than the incoming highest type. A stronger incoming identity requires an upgrade.
2. Compare the highest-priority strong type present in **both** views. Missing types are skipped. A conflict at this
   shared type excludes the candidate; a lower match cannot override it. Non-TLS types match any equal value with equal
   scope. TLS requires equal complete normalized key sets: `{A,B}` matches `{B,A}`, but not `{A}` or `{A,B,C}`.
3. Among reusable candidates, prefer the highest-priority shared match, then newest present `LastSeen`, then smallest
   asset key by byte order. Missing times rank last; compare UTC instants at nanosecond precision. Return `REUSE`.
4. If incoming strong IDs exist but no candidate qualifies, return `CREATE`. Merge planning can still move compatible
   older records under the new key. Use fuzzy matching only when no incoming configured strong ID remains after
   admission.

Lower-priority differences do not veto a higher match. Duplicate values and TLS key order do not add evidence.

## Fuzzy matching

Keep configured weak types and deduplicate by type, normalized value, and scope. Return `REUSE` only for a candidate
containing **every incoming weak identifier**. Otherwise return `CREATE`. An empty weak observation or no candidates
also returns `CREATE`. Partial overlap does not qualify.

The score sums shared distinct-value counts multiplied by weights, rounding count conversion, multiplication, and each
addition to float32 in policy order. A nonfinite score is an error. All qualifying candidates contain the whole
observation and therefore score equally; select the newest `LastSeen` at whole-second precision, then first input
position. Missing time compares as Unix epoch: it ties epoch and outranks pre-epoch times. Fractional seconds do not
break ties. There is no score threshold.

## Merge plan

Compare each source candidate with the destination view: the stored selected candidate for `REUSE`, or the incoming
observation for `CREATE`. The library does not combine these views before planning merges.

| Evidence                                | Merge requirement                                                          |
|-----------------------------------------|----------------------------------------------------------------------------|
| Both views have configured strong IDs   | The source's highest-priority strong type must match in the destination    |
| Either view lacks configured strong IDs | Every source weak identifier occurs in the destination's nonempty weak set |

A Machine-ID + Agent-ID destination can absorb an Agent-only source when the Agent ID matches. A source with a different
Machine ID cannot join through its matching Agent ID. TLS still requires equal complete key sets; other strong types
match any equal scoped value. Lower-priority differences do not veto that match. For strong `REUSE`, also exclude
sources that conflict with the incoming observation at a type stronger than the match that selected the destination.
This prevents merge planning from reintroducing an excluded record. An empty source weak set is contained by any
nonempty destination weak set.

If the destination has no strong IDs, also compare proposed strong-ID sources pairwise. Use the highest-priority strong
type present in either source, with complete-set equality for TLS. Exclude both sources of each incompatible pair.
Compatible strong sources and contained weak sources remain eligible; input order does not choose a winner.

Return merge indices in original input order, excluding the selected candidate. `CREATE` can therefore consolidate older
records under a new key while still returning an empty selected key and nil selected index. The caller preserves earlier
evidence and applies the observation and merges atomically.

## Validation

Validate the policy first, then all candidate keys and timestamps, then all identifiers, including unmatched candidates
and types outside the active policy. Reject empty keys (`ErrEmptyCandidateKey`), duplicates
(`ErrDuplicateCandidateKey`), and present timestamps outside UTC years 1–9999. Do not skip candidates or renumber
indices. Policy errors support `errors.Is(err, ErrInvalidMatchPolicy)`; identifier and time errors retain their
categories.

## Examples

`G` = Greenbone ID, `A` = Agent ID, `P` = IP, `H` = hostname, `M` = MAC. Scopes are equal. Candidate order determines
the zero-based merge indices below.

| Incoming observation | Existing candidates      | Decision      | Selected key | Merge indices |
|----------------------|--------------------------|---------------|--------------|---------------|
| G1, A1               | K0:A1                    | STRONG CREATE | —            | `[0]`         |
| A1                   | K0:G1,A1                 | STRONG REUSE  | K0           | `[]`          |
| G1, A1               | K0:G2,A1                 | STRONG CREATE | —            | `[]`          |
| G1, A2               | K0:G1,A1                 | STRONG REUSE  | K0           | `[]`          |
| G1, A1               | K0:A1; K1:G1,A1          | STRONG REUSE  | K1           | `[0]`         |
| G1, P1               | K0:P1                    | STRONG CREATE | —            | `[0]`         |
| P1                   | K0:P1,H1                 | FUZZY REUSE   | K0           | `[]`          |
| P1, H1               | K0:P1                    | FUZZY CREATE  | —            | `[0]`         |
| P1, H2               | K0:P1,H1                 | FUZZY CREATE  | —            | `[]`          |
| P1, H1, M1           | K0:P1,H1; K1:P1,M1       | FUZZY CREATE  | —            | `[0,1]`       |
| P1, H1, M1           | K0:A1,P1,H1; K1:A2,P1,M1 | FUZZY CREATE  | —            | `[]`          |
| TLS keys {A,B}       | K0:TLS keys {A}          | STRONG CREATE | —            | `[]`          |

## C API

The public header is [`gvm_asset_identity.h`](../../include/gvm_asset_identity.h). Constructors copy raw values;
`gvm_asset_identity_decide` normalizes them. SSH may include a leading port; TLS may be `x509:<base64-DER-certificate>`.

- Constructors return owned objects; parents own their children. Matching free functions accept NULL.
- `decide` borrows immutable inputs and returns an owned decision; on failure the decision is NULL. Output slots must
  not alias inputs or each other. Initialize `GError *` to NULL and free it with `g_clear_error`.
- Use real GLib arrays, owned string-to-string scope tables, and NUL-terminated strings without embedded NUL bytes. A
  NULL scope differs from an empty table. Pointers must reference live, aligned objects of the declared types.
- Timestamps contain presence, signed Unix seconds, and nanoseconds (0–999999999), within UTC years 1–9999. Absent
  timestamps have zero seconds/nanoseconds. No Go pointer crosses the ABI.
- Per call: at most 1,048,576 entries per collection, 16 MiB per string, and 64 MiB of private wire arrays/string bytes.
- Errors are `INVALID_INPUT`, `INVALID_POLICY`, or `INTERNAL`. Recoverable Go panics become `INTERNAL`; fatal runtime or
  allocation failures retain normal process behavior.

ABI 1 installs `libgvm_asset_identity.so -> .so.1 -> .so.<version>-<arch>`, the header, and pkg-config metadata.
Consumers need GLib; Go and Cgreen are build/test dependencies. See
the [README](../../README.md#c-build-test-and-install)
for build/install commands. `DESTDIR` stages files without changing metadata; uninstall removes only project files.
CTest uses `CGREEN_NO_FORK=1` for the Go runtime and clears loader overrides. Cross-builds need matching GLib, compiler,
and sysroot.

## Verification

Run `make test`, `make test-install`, `go test -race ./...`, `CGO_ENABLED=0 go test ./...`, and `go vet ./...`.
The [counting matrix](../../identity/counting_matrix_test.go) covers strong/weak combinations, priorities, scopes,
candidate ordering, merge plans, and progressive counts. Other Go and C tests cover validation, formats, ownership, and
concurrency.

The 78 [C reference fixtures](../../identity/testdata/fuzzy_reference.json) check fuzzy selection, exact score bits, and
merge indices for canonical values with equal scopes, distinct keys, and whole-second timestamps. This library rejects
empty or duplicate keys rather than skipping rows as the reference C code does.
